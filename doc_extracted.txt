Confidential — Internal Project Document  Page 2 System Overview  
This document defines the complete functional requirements, flow specifications, and user navigation maps for 
the Sri Lanka Clothing Boutique  Marketplace Application. It is intended as the single source of truth for the 6 -
member development team.  
 
Concept Summary  
• Authentic boutique sellers are manually verified by platform admins before they can list products.  
• Verified sellers manage their shop  and product listings through the mobile app.  
• Registered customers browse listings, view product details, and place orders through the mobile app.  
• Admins manage the entire platform through a separate web -based admin panel.  
 
Key Business Rules  
1. When a custom er places an order, the system automatically notifies the relevant seller with order and 
customer details.  
2. The seller manually handles packing, packaging, and courier handover.  
3. Shipments use the app company address as the "from" address — not the seller's personal address.  
4. Admins can cancel any order before the seller dispatches/couriers the item.  
5. Payment methods: Card (online) or Cash on Delivery (COD).  
6. All financial operations including seller payouts are managed exclusiv ely by admins.  
7. Only customers who completed an order can submit a review for a product or seller.

4.1  Module Breakdown  
Handles the complete order lifecycle from placement through delivery. Includes automatic seller notification on 
new orders, status progression, payment handling (Card / COD), admin oversight, and cancellati on rules.  
 
Operation  Description  
Create  Customer places an order — selects p roducts, quantity, delivery address, 
payment method (Card or COD). System auto -notifies the seller with full order 
and customer details.  
Read  Customer views order history, order detail, real -time status tracking. Seller views 
incoming orders. Admin views all orders platform -wide.  
Update  Order status progresses: Pending → Confirmed → Shipped → Delivered 
(automated/seller -triggered). Customer or Admin can cancel before dispatch.  
Delete  Soft delete: cancelled or failed orders removed from active view but re tained for 
audit and financial records.

FR4.5  Order Status Lifecycle  
Statuses: Pending → Confirmed → Shipped → Delivered  
Pending: Order placed; awaiting seller confirmation. Admin can cancel a t this stage.  
Confirmed: Seller has acknowledged the order and is preparing it. Admin can cancel at this stage.  
Shipped: Seller has handed over to courier; dispatch address = app company address. Admin CANNOT cancel
